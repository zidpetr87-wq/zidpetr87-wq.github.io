Zásady ochrany údajů

Jak aplikace přistupuje k reportům v Gmailu, k čemu je používá a jak přístup zrušit.

1. Provozovatel a kontakt

Provozovatelem této instance aplikace Enaspol reporty je Petr Žid. Dotazy ke zpracování údajů, přístupům a odstranění pracovních kopií zasílejte na zidpetr87@gmail.com.

Aplikace je určena k internímu zobrazení výrobních reportů. Tento veřejný informační web poskytuje popis aplikace, její podmínky a zásady ochrany údajů.

2. Jaké údaje aplikace načítá

Po udělení souhlasu aplikace ověří e-mailovou adresu připojeného Google účtu. V Gmailu hledá zprávy podle nastaveného odesílatele a příjemce, předmětu, data reportu a názvu TXT přílohy.

U odpovídajících zpráv načítá hlavičky včetně výsledku ověření odesílatele, technické údaje zprávy a příloh, čas přijetí a obsah reportové přílohy. Gmail může při načtení celé zprávy vrátit také její tělo a metadata dalších příloh; aplikace tělo pro sestavení přehledu nevyužívá.

Obsah reportu může zahrnovat výrobní operace, výsledky analýz, provozní poznámky a údaje o zásobnících. Případné osobní údaje obsažené v zaslaném reportu se zpracují jako součást tohoto podkladu.

3. Oprávnění a účel použití

Aplikace žádá rozsah https://www.googleapis.com/auth/gmail.readonly. Toto oprávnění technicky umožňuje čtení celé schránky. Výběr reportů omezuje aplikační kód; nejde o omezení oprávnění pouze na vybranou složku nebo odesílatele.

Údaje slouží k ověření reportové zprávy, načtení vybraného dne a zobrazení výrobních tabulek uživateli aplikace. Čtecí integrace neposílá zprávy, nemaže je, nepřesouvá a neoznačuje jako přečtené.

Samostatná příprava reportu z firemních zdrojů a jeho odeslání do schránky používají oddělená oprávnění. Gmailová integrace popsaná zde slouží k příjmu a zobrazení již doručeného reportu.

4. Uložení a doba uchovávání

Původní zprávy a přílohy zůstávají v Gmailu do doby, než je vlastník schránky odstraní podle nastavení svého účtu. Aplikace jejich odstranění neprovádí.

Na serveru aplikace je paměťová cache nejvýše osmi denních reportů. Platnost pro opakované použití je jedna minuta; po jejím uplynutí další požadavek znovu čte Gmail. Uplynutí této minuty samo o sobě není okamžikem výmazu obsahu z paměti. Kopie se odstraní při nahrazení dalšími reporty nebo při ukončení či restartu serverového procesu.

Gmailová integrace nevytváří trvalý export příloh na serverový disk ani do Git repozitáře. Report se předává prohlížeči jako součást stránky; server nastavuje Cache-Control: no-store. Zobrazený obsah má uživatel dostupný v otevřené stránce. Uložení nebo tisk reportu uživatelem vytváří samostatnou kopii pod jeho kontrolou.

OAuth klientské tajemství a obnovovací token jsou uloženy v neveřejných Secrets provozního prostředí. Přístupové tokeny se používají na serveru; tajemství se nepředávají klientskému JavaScriptu.

5. Předávání údajů a přístup lidí

Načtené údaje se zpracovávají na serveru provozovatele a zobrazují v prohlížeči návštěvníka datové aplikace. V současném provozu je server umístěn v GitHub Codespaces. Provozovatel řídí přístup ke Codespacu a jeho portům; samotný Gmail token nezavádí přihlašování uživatelů do aplikace.

Google zajišťuje schránku a Gmail API, GitHub zajišťuje zvolenou serverovou infrastrukturu. Jejich služby se řídí také zásadami Googlu a zásadami GitHubu.

Údaje z Gmailu se neprodávají, nepoužívají pro reklamu ani pro trénování zobecněných modelů umělé inteligence. Gmailová integrace nepředává obsah zpráv do modelů umělé inteligence. Lidé mohou k údajům přistupovat jako oprávnění uživatelé reportu nebo při výslovně povolené podpoře, řešení bezpečnostního incidentu či plnění právní povinnosti.

6. Pravidla Google a Limited Use

Použití informací přijatých prostřednictvím Google API a rozsahů Google Workspace v aplikaci Enaspol reporty se řídí Google API Services User Data Policy a Google Workspace API User Data and Developer Policy, včetně požadavků Limited Use.

7. Odvolání přístupu a odstranění údajů

  1. Otevřete připojení ve svém Google účtu, vyberte tuto aplikaci a odeberte její přístup.
  2. Provozovatel odstraní uložený obnovovací token ze Secrets a restartuje server, aby odstranil i paměťovou cache. Již otevřené reporty v prohlížeči zavřete.
  3. Pokud chcete odstranit i původní zprávy, smažte je v Gmailu včetně koše. Případné vlastní exporty nebo vytištěné kopie spravujte samostatně.

Odebrání přístupu zastaví budoucí čtení Google účtu; samo neodstraní již doručené zprávy ani dříve vytvořené kopie. Pro dotazy, opravu nebo odstranění pracovních kopií kontaktujte zidpetr87@gmail.com.

8. Veřejný informační web

Informační stránky nepoužívají analytické ani reklamní skripty, formuláře nebo aplikační cookies. Hostitel GitHub Pages může pro zabezpečení evidovat technické údaje návštěvy včetně IP adresy podle svých zásad ochrany údajů. Z tohoto webu se nepřipojujete ke své schránce ani k reportovému serveru.

9. Změny zásad

Aktuální znění a datum platnosti jsou uvedeny na této stránce. Při změně účelu zpracování nebo požadovaných oprávnění provozovatel aktualizuje informace a vyžádá nový souhlas, pokud je potřebný.
